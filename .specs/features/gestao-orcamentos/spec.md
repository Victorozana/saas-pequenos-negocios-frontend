# Gestão de Orçamentos Specification

## Problem Statement

Atualmente a aplicação não dispõe de uma interface consolidada para que os prestadores possam gerenciar (listar, buscar, criar, aprovar, rejeitar) orçamentos (Quotations). Os usuários precisam enviar orçamentos formais (PDFs) para clientes contendo os detalhes dos serviços, quantidades, preços unitários e descontos.

## Goals

- Listar orçamentos do tenant com paginação, busca e filtro de status (Draft, Sent, Approved, Rejected).
- Permitir a criação de orçamentos vinculando-os a um cliente ativo.
- Suportar a adição de múltiplos itens de serviço (text-livre) por orçamento com cálculo de subtotais e total em tempo real no frontend.
- Permitir a transição de status dos orçamentos.
- Disponibilizar a exportação do orçamento no formato PDF, consumindo a rota de geração do backend.
- Proteger todas as rotas de API com validação de cookie de sessão autenticada (`agendamento_session`).

## Out of Scope

| Feature | Reason |
| --- | --- |
| Catálogo Fixo de Serviços (Autocomplete) | Decisão de iniciar com free-text `ServiceName` para flexibilidade imediata antes de criar a API do catálogo de serviços completo. |
| Edição de orçamentos (Update total) | A prioridade MVP é gerar, enviar e mudar status. Edição total pós-criação fica para um roadmap posterior ou requer transições cuidadosas (só pode editar em Draft). |

## User Stories

### P1: Listar e Pesquisar Orçamentos ⭐ MVP

**User Story**: Como prestador autenticado, quero listar e buscar os orçamentos emitidos para poder acompanhar os orçamentos em aberto, aprovados ou rejeitados.

**Acceptance Criteria**:

1. WHEN an authenticated user visits `/orcamentos` THEN the system SHALL request the quotations list via `GET /api/quotations?search={term}&status={status}&page={page}` and render a paginated list. <!-- ORC-001 -->
2. WHEN the user clicks on a status filter THEN the list SHALL filter only the specified status. <!-- ORC-002 -->
3. WHEN the user types in the search input THEN the system SHALL filter the list based on customer name or document. <!-- ORC-003 -->
4. WHILE data is loading THEN the system SHALL display an accessible skeleton loader. <!-- ORC-004 -->
5. WHEN the list is empty THEN the system SHALL display a friendly empty state "Nenhum orçamento encontrado" with a button to create one. <!-- ORC-005 -->

### P1: Criar Novo Orçamento ⭐ MVP

**User Story**: Como prestador autenticado, quero criar um novo orçamento incluindo as métricas (quantidade, preço unitário, unidade e nome do serviço) para fechar novos negócios.

**Acceptance Criteria**:

1. WHEN the user clicks "Novo Orçamento" THEN the system SHALL open a dynamic modal or form. <!-- ORC-006 -->
2. THE modal SHALL include a Customer selector (via API lookup or minimal list). <!-- ORC-007 -->
3. THE modal SHALL allow adding multiple Service Items dynamically (Name, Unit, Quantity, Unit Price, Discount). <!-- ORC-008 -->
4. WHEN the user modifies item values THEN the system SHALL display a real-time Total Price preview (`(Quantity * Unit Price) - Discount`). <!-- ORC-009 -->
5. WHEN the user submits a valid form THEN the system SHALL send `POST /api/quotations`, validate the payload, and display success feedback. <!-- ORC-010 -->

### P1: Alterar Status e Exportar PDF ⭐ MVP

**User Story**: Como prestador autenticado, quero alterar o status do orçamento quando um cliente aprova/rejeita e baixar um PDF da proposta para enviá-lo por e-mail ou WhatsApp.

**Acceptance Criteria**:

1. WHEN the user changes a quotation status THEN the system SHALL send `PATCH /api/quotations/[id]/status` with the new status and refresh the list. <!-- ORC-011 -->
2. WHEN the user clicks "Baixar PDF" THEN the system SHALL trigger `GET /api/quotations/[id]/export` which downloads the PDF generated by the backend (`QuestPdfQuotationGenerator`). <!-- ORC-012 -->

## Success Criteria

- O prestador consegue visualizar, filtrar, criar e gerir status de orçamentos em `/orcamentos`.
- Os cálculos do TotalPrice e TotalAmount previstos no formulário conferem com as regras aplicadas pelo backend no momento de salvamento.
- A função de exportação de PDF inicia com sucesso o download de um arquivo válido gerado pelo backend.
- Rotas e componentes cobertos com testes de falhas de rede (Safe failures).
